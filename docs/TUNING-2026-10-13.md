# Motion tuning — October 13, 2026

The retained browser trials show that faster serial updates alone did not fix
wide sine tracking. Increasing native acceleration or position gain also left
failures. Bypassing the native acceleration process with **register 3 = 60000,
0% position feedforward and position gain 3000** passed the first broad trial
with more following-error margin. This is a candidate supported by bounded
measurements, not evidence of perfect motion across patterns, loads or timing
interruptions.

## Scope and measurement method

These captures used local development and private browser exports. The first
comparisons ran the serial/planner loop on the main thread; the later worker
comparisons are recorded separately below. Final physical validation and a
production release remain pending. These trials are separate from the published version recorded
in [the earlier release evidence](RELEASE-2026-10-13.md). No firmware flash or
EEPROM parameter-save command was part of these tuning comparisons. Changes to
native settings were volatile and read back before the bounded comparisons.

The drive was connected through the CH340 adapter at 115200 baud. Home measured
approximately 179.7 nominal mm; conversion assumes 32768 encoder counts per
40 mm revolution. Center was 50%, software limits 10–90%, patches empty, and
the envelope-to-stroke connection disabled. The requested 1 and 1.5 Hz slider
values were 0.9989117144 and 1.4985372651 Hz in the exports. Host limits remained
1080 mm/s, 6000 mm/s² and 100000 mm/s³.

The numeric diagnostic ring records cycle start, completed guard checks, native
submission, validated reply, current and preceding targets, reported encoder,
following error, guard age and the consecutive failure count. Later captures
also record actual gain settings, generation time, planned velocity and
acceleration, and the encoder from an already-required guard read. A profile
label retained by an experimental export is not proof of the raw drive setting;
the tables use recorded register values.

Following error compares each fresh FC7b encoder reply with the **preceding
accepted target**, because the immediate reply cannot establish arrival at the
newly submitted point. Its unchanged budget is approximately 17.57 nominal mm
on these rails, with a fault after three consecutive fresh failures. A short
pass can contain one or two samples above that budget and therefore have
insufficient margin. All listed attempts ended with **Stop confirmed**,
including the failed attempts. The 250 ms status fence, alarm, output,
configuration, rail and Stop checks remained active.

Command rate below is `(N−1)/(last submission−first submission)` over retained
rows. Duration ends at the last validated reply relative to trace start; it
excludes subsequent Stop verification. The 4096-row ring dropped the beginning
of the 25.305 s feedforward capture: its retained submission window was
0.769–25.299 s, so its rate and extreme values describe that window. Later
exports explicitly record total commands and dropped rows. Neither command
rate nor duration is waveform frequency or carriage speed.

## Worker comparisons and remaining validation

A dedicated worker now owns the planner, serial reader/writer and watchdog.
The window sends controls and a heartbeat, rather than messages for individual
targets. An independent Node worker test using the actual runtime and WASM
confirms that a new target is generated during a blocked window thread, without
window IPC during that interval. This proves ownership isolation, not a physical
command rate or immunity to USB/OS delays.

The physical worker trials used the same host limits and zero native position
feedforward. Home continued to calibrate with gain 3000. Private exports also
tested a volatile run gain of 6000; that value is not the reviewed default.

The 6000 gain reduced fitted delay and broad-stroke following error, but its

Unequal trial lengths and receive-time uncertainty limit that comparison.
The reviewed build retains gain 3000; no new trial was watched for human
smoothness acceptance.

The continuity fence checks accumulated unsent path travel, including
reversals, against the existing following corridor before sending another
target. It prevented a catch-up jump in the faulting worker trials. It retains
the configured velocity/acceleration/jerk limits and full command cadence.
The new continuity recovery requires its typed fault code before Clear fault
can preserve Home, plus confirmed Stop and three fresh, inhibited, stationary
samples inside the original usable rails. Existing narrowly allowed
communication/settle recovery remains available with fresh strict readbacks.
Following, configuration, alarm and rail faults still require reconnect/Home.

New stopped diagnostics separate native submission, writer completion, first
and last response chunks, and validated exchange time. A slow small-stroke
exchange took 0.5 ms to settle the write, 60.4 ms to the first response chunk and
61.6 ms to validation. This places most delay after write acceptance but does
not distinguish drive, adapter, OS or worker scheduling. An independent 20 ms
timer ring and a retained continuity-gap record were added to narrow that
uncertainty on the next physical run; their final physical validation is pending.

The final checked source passes **376 browser tests and 134 Python tests**.
[Aggregate worker evidence](qa/2026-10-13-worker-tuning.json) records the

## Why two motion processes can matter

The [vendor manual, physical pages 8 and 11](https://www.robotanno.com/web/userfiles/download/ACCESSORIES/IntegratedServoMotor/YZ-AIMManual_v2_55.pdf)
describes the native acceleration process as adding following lag. Register 3
below 60000 enables it. At 60000 there is no internal acceleration process;
deceleration depends on position KP. Values 60000–60098 encode 0–98% position
feedforward. **60000 is not 60000 RPM/s** and does not disable the closed
position/speed loops.

The host retains continuous position, velocity and acceleration, but FC7b sends
only sampled positions. Those form a held staircase at the drive input. A
second native motion process can reshape that input even when its nominal
33333 mm/s² setting exceeds the host 6000 mm/s² budget. At 463 mm/s, ideal
braking distance at the native budget is 3.22 mm, while a 5 ms position step is
only 2.32 mm. **If** native point moves use rest endpoints, that spacing could
encourage braking between updates. The manual does not establish that endpoint
rule or a velocity reset; this explanation remains conditional. Bypassing the
documented acceleration process tests the broader two-process hypothesis.

The earlier 60098 / 98% feedforward run described as a jackhammer used roughly
20 updates/s and the old pursuit planner; see [the historical comparison](MOTION_PLANNER_AUDIT.md).
It does not establish the result of this dense C2 / 0% feedforward comparison.
Conversely, low following error alone cannot establish pleasant motion.

## Timing and smoothness limits

Clean FC7b pairs already add no artificial quiet delay. At 115200 baud an
eight-byte request plus reply needs 1.389 ms of wire time, while the retained
browser median round trip was about 4.6–4.8 ms. A 4.6 ms serialized exchange
limits clean throughput to about 217/s before guard traffic. No trial reached
500 Hz. Atomic full snapshots reduce repeated USB round trips while keeping
the 250 ms receipt-age fence.

The [Modbus guide, section 2.5.1.1](https://www.modbus.org/file/secure/modbusoverserial.pdf)
recommends 1.75 ms ordinary inter-frame delay above 19200 baud. Changing the
current 2 ms ordinary boundary would save only about 0.5% at 8–10 full snapshots
per second, without explaining the large scheduling gaps. [Web Serial exposes
port access to DedicatedWorker](https://raw.githubusercontent.com/WICG/serial/main/index.bs),
while the permission chooser remains on Window. Worker behavior requires its
own validation; it cannot be inferred from these main-thread captures.

Encoder resolution is 0.0012207 nominal mm/count. At uniform 5 ms spacing,
quantization alone can contribute up to 0.244 mm/s to first differences,
97.7 mm/s² to second differences and 39063 mm/s³ to third differences. Unknown
sample-time jitter adds more: 1 ms at 463 mm/s can produce 0.463 mm of apparent
position residual. Raw per-reply jerk therefore cannot prove physical jerk
compliance.

Useful comparisons retain raw gaps and extreme steps, fitted lag, amplitude
ratio and lag-aligned residual RMS/p99/maximum. Derivative estimates should use
local polynomial fits over 20–40 ms with the actual irregular timestamps and
flag insufficient samples or large gaps. Such filtering must not hide failed
segments. Physical acceleration, torque, vibration and human smoothness still
need direct observation; mathematical host limits are not those measurements.
